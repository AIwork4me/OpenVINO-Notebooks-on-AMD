- 13 rows are BLOCKED_NETWORK on this validation runner's egress allowlist
  (github.com git/assets, storage.openvinotoolkit.org, raw.githubusercontent.com
  foreign-repo fetches). Several of them (muse-glimmer: PROVEN_CPU events;
  llm-code-assistant: conversion completed) are partial-success rows whose
  remaining blocker is purely network egress.
- 3 rows (llm-rag-langchain, ltx-video, segment-anything-2-video) carry
  evidence recorded on a pre-329562e pin (`a8809170c`) whose notebook content
  changed before that pin; revalidation queued (same 3 warnings as v0.2.1's
  audit — carried, documented, not silently refreshed).
- openvino-tokenizers' upstream fix is in nightly builds this network cannot
  reach; the row stays FAILED_COMPATIBILITY until a stable release > 2026.4.1
  containing the `connect_models` sink fix is installable here.
- Single-run (REPEATABILITY_NOT_ESTABLISHED) yellows include the large-model
  recoveries (qwen3, flux.1, parler-tts, llm-chatbot) — disk/time budget on
  this runner bounds repeatability; limitation codes recorded per row.
- Ingest workflow has no end-to-end green run (infrastructure, above).
- Freshness checking is a script + committed record (`reports/upstream-freshness.json`);
  a scheduled workflow wiring is future work.
