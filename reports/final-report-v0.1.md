## Shared issues fixed during the campaign (each unlocked multiple notebooks)

1. **No pip in uv-created venvs** — every `%pip install` cell failed instantly;
   seeded pip into both venvs.
2. **Black-holed IPv6 to major CDNs** — python (no happy-eyeballs) burned 30s+
   per connection or hung; installed an IPv4-first getaddrinfo hook via `.pth`
   in both venvs (32s → 0.2s connect).
3. **Unbounded `requests.get` hangs on blocked CDNs** — global 75s default
   socket timeout via the same hook; cells now fail fast and classify as
   NETWORK instead of stalling the campaign.
4. **`notebook_utils.py` fetched from raw.githubusercontent** (nearly every
   notebook) — pre-seeded from the pinned snapshot; also pins
   `device_widget` default to CPU (AUTO silently picked the enumerated GPU).
5. **`optimum-cli` missing** (optimum-intel never in baseline) + version
   mismatch optimum 2.3 vs optimum-intel 1.15 — golden set + env health check
   between workloads repairs drift caused by in-notebook `%pip install`.
6. **UI-only tail cells** (gradio `demo.launch()`) blocked headless runs —
   default skip policy: `CORE_INFERENCE_VERIFIED; INTERACTIVE_UI_NOT_TESTED`
   → VERIFIED_WITH_LIMITATIONS.
7. **Cell-substitution delimiter** — patterns containing `https://` corrupted
   notebook cells when the engine split on the first ':'; switched to `||`.
8. **Concurrent state clobbering** (CPU marathon vs GPU twins writing
   marathon-state.json) — merge-on-write checkpointing by `updated` timestamp.
9. **hf-mirror 401 for stabilityai/deepseek-ai repos; xet CAS endpoint 401** —
   ModelScope fallback (recorded per-attempt), `HF_HUB_DISABLE_XET=1`.
10. **git clone RPC timeouts at ~47KB/s** — global patient-git config.

## Upstream findings (candidate issues)

- OpenVINO `FULL_DEVICE_NAME` query against the NPU device raises on this
  stack (hello-npu) — Intel-NPU-specific surface.
- blip-visual-language-processing: conversion API rejects a documented
  example_input type on OpenVINO 2026.4.
- several notebooks `%pip install` pinned versions that conflict with the
  current stack (transformers 4.x pins downgrade 5.x mid-session).

## Resource limits / environment constraints

- huggingface.co unreachable; stabilityai + deepseek-ai repos 401 on the
  reachable mirror → ModelScope substitution (recorded)
- github bulk transfer throttled (~47KB/s): in-notebook `git clone` of large
  repos frequently exceeds cell timeouts
- shared 94GB RAM domain between CPU validation and GPU twins; large-model
  concurrency avoided by design
